3. Error handler fall-through: 413, bad URL become 500 INTERNAL_ERROR; 429 "(RFC-010 handles)" with no interim behaviour.

## RFC-002 Link Creation
Guesses:
1. Validator configuration: AC19 needs unknown fields and non-string url to return VALIDATION_FAILED; Fastify's default Ajv strips additional properties and coerces types, so both pass silently. No Ajv options given.
2. Schema strictness vs service errors: AC9/AC13/AC17 require INVALID_ALIAS/INVALID_EXPIRATION/INVALID_URL, so the TypeBox schema must not carry pattern/format/maxLength -- unstated; API-2 invites adding them.
3. null and empty optionals (alias "", alias null, expiresAt null): absent or error? RFC-009's form sends empty strings.
4. Expiration grammar: "RFC 3339" but the regex allows missing seconds, rejects >3 fractional digits and lower-case t/z; 2026-02-31 passes the regex and new Date may roll it to March.
5. "Malformed": new URL accepts http:example.com, backslashes, strips whitespace; the "not trimmed" note misdescribes the result.
6. Logger source: createShortUrl logs but deps has no logger and ARCH-3 bars request.
7. Stubbing generateCode (AC3): module function, no injection point.
8. Where the catch for check() throwing lives.
Weak criteria: AC20 does not prove no request was attempted. AC2 "retrievable as its own link" has no retrieval endpoint in this RFC. AC4 cannot fail (reserved words all < 7 chars) without stubbing both generator and list. AC6, AC14, AC22 are universal negatives.

## RFC-003 Redirect and Click Recording
Guesses:
1. MaxMind endpoint and auth left to the implementer (LINKSNIP_GEOLITE2_ACCOUNT_ID?); test needs a URL override, which becomes an OPS-4 config variable.
2. DB failure on the lookup: only insert failure handled; no query/acquire timeout, so a slow database hangs redirects despite ERR-3.
3. GeoLite2 file lifecycle: name, age source (mtime or Clock), stale file while re-downloading ("null until it finishes" vs "keeps the current reader"), 7-day timer from boot or file age; default /tmp means every restart re-downloads.
4. safe(): ERR-2/ERR-3 require geo and bot failures logged; pseudocode swallows them, no event named.
5. Non-matching paths: regex constraint implementation; does /ab get the same no-store 404 (AC6 vs AC9)?
6. Custom bot list: regex flags, empty or all-comment file, empty UA when list replaced; isbot export name "verify".
7. IPv4-mapped IPv6 "must resolve like IPv4": no method.
Contradictions: AC2 "extra path does not change Location" but /{code}/x does not match the route (404, not 302). OPS-5 "downloaded at startup" vs download after listen and weekly. F12 "logged and counted", only logging specified. HEAD records no click vs FR-8 "each redirect".
Weak criteria: AC5 counting queries does not verify "no other network call". AC14 how to send from a known IP without trustProxy. AC18 needs fake timers. AC6 "identical headers" needs exclusions (Date).

## RFC-004 Redirect Load and Durability Tests
Guesses:
1. Seed duplicates: 10M random 7-char codes give ~14 expected duplicate pairs; COPY aborts the batch on a unique violation; AC1 demands exactly 10,000,000 rows. No dedupe/retry.
2. Reference host: only "2 vCPU / 4 GB"; fsync/storage unspecified, so the OQ-7 verdict changes with storage; k6 co-located or separate.
3. constant-arrival-rate has no ramp; do ramp samples count?
4. Server-side latency: log capture, field names, windows unstated; server-latency.ts only "reports", nothing asserts NFR-1's server-side figure.
5. Seed mechanics: how it reaches the DB, column list, --force append or truncate, which 10,000 codes are active.
6. Durability setup: which code/id, seeded or empty DB, clock for T0, rate-limit override; truncate clicks unguarded.
Contradictions: "no new npm dependency" vs COPY FROM STDIN via pg needing pg-copy-streams (STACK-4). Verdict when k6 fails but server-side passes (NFR-1 is server-side, AC2 fails the script, AC7 says stop). "Does not change the write path" vs allowing removal of the clicks FK (a migration). Allowed tuning does not exclude synchronous_commit=off, which breaks NFR-9.
Weak criteria: AC4 one kill at one instant, no repetition. AC6 needs hardware the implementer may not have. AC7 is a process rule. AC5 documentation only.
