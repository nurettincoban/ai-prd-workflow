# Cold read: RFC-005

1. **Interfaces the tests need are defined only in RFC-001 and RFC-002, which are not in the folder.** Only RFC-003 was supplied. The criteria depend on these items:
   - the data file's key names, version number and layout (`generated by the test`, the 5,000-task file in criterion 5, and `tests/fixtures/v1.json`; DATA-1 says "exact key names are for the RFC");
   - the name `DEFAULT_FILE` (criterion 9) and `helpers.temp_env()`;
   - where `td` sits relative to `tests/` ("the file `td` alone is copied");
   - the contents of "RFC-001 criterion 7" and "criterion 12".
   I would have to guess the schema to build the 5,000-task file. RFC-005 itself lists the fixture tasks, but not the JSON keys.

2. **Criterion 5 (speed) can pass by luck and misses the save path.** The criterion reads "copied fresh for each of `td list`, `td add x`, `td done 1` and `td rm 2`; each is run ... three times ... median ... under 1 second".
   - The fresh copy is made once per command, not once per run (the wording is ambiguous).
   - Runs 2 and 3 of `td done 1` hit the already-done path, which skips `save_store` (RFC-003, CLI-3).
   - Runs 2 and 3 of `td rm 2` fail with exit 1 before any save (task 2 is already gone).
   - So the median measures the cheap no-save path, not the write of 5,000 tasks.
   - Exit codes are not asserted, so a failing command still counts as fast.
   - Fix: copy the file fresh before every run, and assert exit 0.

3. **Subprocess environment is unspecified.** Criterion 4 asserts exact non-ASCII output (`naïve café`). OUT-6 makes non-UTF-8 locales print `?`.
   - Criteria 3 to 5 do not say which `LANG`, `LC_ALL` or `PYTHONUTF8` the subprocess gets, so the result depends on the host locale.
   - Criterion 3 does not say whether the bare name `td` is resolved through the `env` passed to the subprocess or through the parent's `PATH`.
   - Criterion 6 does not say which interpreter ("`python3`" or `sys.executable`) or which working directory the nested run uses.

4. **Criterion 6 may conflict with other tests.** It requires that "the temp `HOME` contains no `.td.json`", with `TD_FILE` unset.
   - TEST-7 requires tests of the unset variable and of `~` expansion. Those tests only avoid creating `.td.json` in the nested `HOME` if they set their own `HOME`.
   - The RFC does not say they must.
   - The check catches `HOME`-based fallbacks only.

5. **Criterion 7 cannot check everything it claims.** The criterion reads "no syntax newer than 3.10".
   - `ast.parse(feature_version=(3, 10))` on 3.12 or later does not reject PEP 701 f-strings (for example nested same-quote `f"{x["a"]}"`). That syntax is newer than 3.10 and can pass.
   - "every file in `tests/`" includes `tests/fixtures/v1.json`, which is not Python and fails `ast.parse`. I assume it means `*.py` files.

6. **Criterion 9 contradicts DEV-4 on docstrings.** It reads "no string constant containing `/` or `\`, other than the value of `DEFAULT_FILE`".
   - DEV-4 requires docstrings and help text. A docstring or help string like "and/or" or "read/write", or an error message with a path, fails the scan.
   - The RFC does not say whether docstrings are exempt.
   - "`os.sep`-style string concatenation" is undefined. It does not say which names or patterns the scan must flag (`os.sep`, `os.path.sep`, `os.altsep`, `+ "/" +`).
   - A narrower reading (flag `os.sep` use only) gives a different test.

7. **Criterion 8 is not a test, and "all four" is ambiguous.**
   - It is a manual run recorded in a section that "does not exist yet". An implementer cannot satisfy it in an automated run, and the RFC does not say whether it blocks "done".
   - "all four" (3.10, newer Python, Linux, macOS) does not say whether that means four separate runs or a matrix such as 3.10 on macOS.
   - TEST-9 says "A test runs the suite on Python 3.10". RFC-005 treats this as manual.

8. **Criterion 2 leaves the detection scope of its scan open.** It reads "contains no call to `os.system` ... `eval`, `exec` or `__import__`".
   - It does not say whether aliases are caught (`from os import system as s`, `import os as o`, `getattr(os, "system")`).
   - A lax scan passes, so the guard Open Question 3 wants ("cannot be bypassed by a dynamic import") is not enforced.
