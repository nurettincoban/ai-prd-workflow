# Cold read: RFC-004 (`td clear`)

1. **Undeclared dependency on RFC-003; criterion 2 cannot be run from what is given.** Criterion 2 says "the next `td add` then gets id 4 exactly (not 3, not 5)". The header says `Depends on: RFC-001, RFC-002`, and RFC-003 (`add`, its output line, its argument rules) is not among the files. An implementer building RFC-004 alone has no `add` command. They would have to guess either that RFC-003 exists first or that the test may call `add_task` directly or read `next_id` from the file. "gets id 4" is also not checkable by stdout, because the line `add` prints is RFC-003's. Fix: add RFC-003 to `Depends on`, or reword criterion 2 to check the file's `next_id` and the id `add_task` returns.

2. **Whether to build it is left to the implementer's judgment, with no criterion.** Summary: "built only if time allows in the weekend". The observable result differs: with `clear` built, `td clear` exits 0, and without it, exit 2. Nothing says who decides or how a test tells "skipped" from "forgotten". The "skipped" branch has no acceptance criterion, for example `td clear` exits 2 with a `td:` line while RFC-004 is unbuilt. It also points at RFCS.md, which is not provided.

3. **Criterion 5, `td clear ""` and `td clear extra`, relies on unpinned RFC-002 wiring.** RFC-002 says "extra-argument handling [belongs] to each command's own RFC". RFC-004 only says "it takes no arguments" and "an argparse error (extra argument) is exit 2". Neither RFC says how the `clear` subparser is declared from the `COMMANDS` iteration, or that an unrecognized-arguments error from a subparser goes through RFC-002's `error()` override. If a subparser is built with a plain `ArgumentParser` class, the output is argparse's usage block rather than one `td:` line, and "exactly one stderr line starting with `td:`" fails. The criterion catches this, but the RFC leaves the guess of where the parser definition lives.

4. **Criterion 1, "prints exactly `2 [ ] <its text>`", has no fixed fixture text.** `<its text>` is a placeholder, so the expected line is only known relative to whatever the test wrote. This is harmless but weak. Criterion 4's "no temp file is left" passes trivially when `save_store` is never called. Only "byte for byte unchanged" with a non-canonical fixture checks the no-save behavior, and that part is checkable.

No contradictions found among RFC-004, RFC-001, RFC-002, RULES.md and FEATURES.md F10. Error precedence (argparse exit 2, then corrupt file exit 1) matches RFC-002's order of events.
